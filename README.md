# NTU_DataMining_Assignment2
#The library contains the two raw, unprocessed data, as well as the code to implement Apriori and FP-growth, respectively. The first dataset is small, containing about 7500 transactions and 120 unique items. The data sparsity is low, and it can be directly used for experiments without complex preprocessing. In order to study the influence of the number of transactions on the algorithm, five subsets with different number of transactions are generated, and the number of unique items in each subset is basically stable. The second dataset is larger, with 88,162 transactions and 16,470 unique items, which is highly sparse. In order to avoid memory overflow, 2117 high-frequency items with support ≥0.001 are screened out, and 86190 non-empty transactions are retained. Then five subsets are generated from them, and the number of unique items in each subset is fixed to about 2000 to ensure the uniqueness of the experimental variables. The Apriori algorithm iteratively generates candidate itemsets and prune low support itemsets. The FP-growth algorithm directly mines frequent itemsets by constructing a compact FP-tree to compress data and avoid redundant steps of candidate set generation. The brute-force algorithm computes the support by enumerating all possible combinations of items (complexity O (2^m), where m is the number of unique items), and the time is estimated by fewsample calibration, which takes 0.2797 seconds on a small sample of 10 items and 1000 transactions to calculate the constant C. And then to large-scale data. The evaluation index mainly includes the total time consumption (and the time variation trend with the increase of the number of transactions).
